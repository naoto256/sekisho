# site/

Source for <https://naoto256.github.io/sekisho/>. Eleventy, no framework,
no client-side JavaScript.

## What is here

```
eleventy.config.js        passthrough copies and watch targets
lib/
  config.js               base path, canonical origin, repository URL
  layout.js               the one page shell every page renders through
  asset.js                content-hashed ?v= query for static assets
  content.js              guides + the book: SUMMARY parsing, link rewriting
  highlight.js            small build-time syntax highlighter
src/
  index.11ty.js           landing page
  docs.11ty.js            one page per chapter of ../docs/src
  guides.11ty.js          the guides and their index
  sitemap.11ty.js         sitemap.xml
  style.css               design system (see below)
  mark.svg                the 関 mark, also the favicon
  guides/*.md             worked examples
test/
  links.mjs               every internal link and anchor in dist/ must resolve
  content.test.mjs        docs/src is a boundary; raw HTML is a trusted-source
                          contract, not a general capability
  sitemap.test.mjs        the sitemap and the built site agree on what exists
```

## The book is rendered here, not mounted

`/docs/` is generated by `src/docs.11ty.js` from `../docs/src/*.md`, one
page per `SUMMARY.md` entry, inside the same shell as the rest of the
site. An earlier version mounted mdBook's own HTML output instead; that
meant walking from the landing page into the reference changed the header,
the sidebar and the typography halfway through.

`docs/book.toml` is untouched and `mdbook build docs` still works — it is
the local preview path for the book on its own. The site simply does not
consume its output, and the published site carries no mdBook chrome. The
cost is mdBook's full-text search, its collapsible sidebar and its theme
switcher, none of which the site replaces.

Two consequences worth knowing when editing `lib/content.js`:

- Heading ids follow **mdBook's** rule, not markdown-it's default. The
  book's cross-references are hand-written against the ids mdBook
  produces, and mdBook drops punctuation rather than encoding it
  (`### 3. API-version-gated clients` → `3-api-version-gated-clients`).
- Links in the source are relative to the file they appear in and point
  at `.md`. Both are resolved and rewritten at render time.

## Commands

```sh
npm ci                    # install, lockfile-exact
npm run build             # -> dist/
npm run check:unit        # docs/src containment, sitemap/route agreement
npm run check:links       # every internal link and anchor in dist/
npm run format:check      # prettier
npm run dev               # watch + serve on :8089, output to .dev/
```

CI runs the first four in that order. `check:links` needs `dist/`, so the
build comes first; `check:unit` reads the source and is placed before the
whole-site sweep so the most specific failure surfaces first.

`SITE_BASE` defaults to `/sekisho/` (GitHub project Pages). Build with
`SITE_BASE=/` to serve `dist/` from a root, which is what a local static
server wants:

```sh
SITE_BASE=/ npx @11ty/eleventy --output=.preview
```

`SITE_ORIGIN` defaults to `https://naoto256.github.io` and is used only
for `<link rel="canonical">` and the sitemap.

Node version is pinned in `.node-version` (24.20.0); CI reads it through
`actions/setup-node`.

## Deployment

`.github/workflows/site.yml`. On a pull request touching `site/`,
`docs/src/` or the workflow itself, it builds and runs the unit, link and
format checks — it does not publish. Publishing is `workflow_dispatch` on `main`
only, so a merge never deploys as a side effect; someone has to ask for it.

**GitHub Pages is not enabled on this repository** —
`gh api repos/naoto256/sekisho/pages` returns 404. The workflow is
complete and its build path is exercised, but the deploy step has never
run successfully and cannot until Pages is enabled with
`build_type: workflow`. That is a repository setting, not something in
this tree.

## Design language

Deliberately not the limpid site. limpid's is a lens: light, airy,
numbered principle cards. This one is a checkpoint.

- **The barrier.** A doubled horizontal rule is the recurring motif —
  content passes under it. Sections are separated by rules rather than by
  cards or shadows.
- **Sumi and washi.** Near-black ink on warm off-white, inverted for dark
  mode. One accent only: a vermilion drawn from a seal (`--seal`), used
  for the stance labels and hover states. Nothing else is coloured.
- **Stances, not features.** The four blocks state design positions and
  their consequences, because the interesting thing about sekisho is what
  it refuses to do, not a feature list.
- **No stock imagery, no gradients, no rounded cards.** Radius is 2px
  where it exists at all.

Type is the system stack with `palt` enabled so the Japanese in the
wordmark sits correctly next to Latin. The mark is the same artwork the
web UI serves as its own logo, so the two do not drift apart.

## Known gaps

- **No social preview image.** The pages therefore declare
  `twitter:card=summary` rather than `summary_large_image`; a large-image
  card with no image renders worse than a small one. Generating an
  `og.png` is deliberately out of scope rather than forgotten.
- **No downloads link.** The header omits it rather than pointing at a
  release tag that is not published yet.
- Screenshots and their capture conditions are recorded in
  `SCREENSHOTS.md` in this directory.
